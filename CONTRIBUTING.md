# Como contribuir

Contribuições são bem-vindas. Antes de abrir uma proposta, verifique se o código mantém o escopo educacional e analítico do projeto: não inclua alegações de previsibilidade de sorteios, retorno garantido ou recomendações de investimento.

| Etapa | Requisito |
| --- | --- |
| Escopo | Explique a finalidade e o impacto da alteração na issue ou no pull request. |
| Qualidade | Execute `pnpm check`, `pnpm test` e `pnpm build`. |
| Segurança | Não inclua arquivos `.env`, chaves, tokens, dados pessoais ou dumps de banco. |
| Testes | Acrescente ou atualize testes unitários para regras novas. |
| Documentação | Atualize o README quando a alteração afetar execução, segurança ou comportamento público. |

Commits devem ser curtos, objetivos e descrever o que mudou. Pull requests devem conter o resultado dos comandos de validação e uma descrição clara de limitações conhecidas.
